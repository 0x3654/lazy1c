# lazy1c

TUI в стиле lazygit/lazydocker для администрирования кластеров 1С:Предприятие.
Один бинарник, Go. Поддерживает **обе линии платформы** через общий интерфейс
`internal/engine.Conn`:

- **8.3 / 8.5** — нативный клиент протокола RAS (порт 1545), `internal/ras/`
- **8.2** — реверс-инжиниринг MMC-протокола ragent (порт 1540), `internal/ras82/`

## Обязательное чтение

- **[internal/ras82/PROTOCOL.md](internal/ras82/PROTOCOL.md)** — находки реверса
  протокола 8.2: кадровка, NTLM, словарь, семантика uuid сеансов (d5/95-теги),
  terminate, быстрый опрос. Не трогать ras82 без этого документа.
- **[internal/mmc83/PROTOCOL.md](internal/mmc83/PROTOCOL.md)** — реверс 8.3-MMC
  (ragent:1540 без RAS): рукопожатие одним конвертом, сессия от клиента,
  кадры списков/мутаций из эталонного захвата spy83. Не трогать без него.
- README.md — пользовательская сторона (клавиши, конфиг, команды).

## Архитектура в двух словах

- `internal/engine` — выбор движка (`engine.New(addr, timeout, "auto|ras|82")`);
  потребители: TUI (`internal/ui`), `dump` (main.go), `ctl` (internal/cli).
- `internal/ras82` — шаблоны-реплеи кадров (templates.go, привязаны к потоковому
  словарю конкретного сервера: vmFrames/prodFrames), адаптер в serializev1-типы.
- Конфиг `lazy1c.toml`: `[[cluster]]` с `engine = "auto"|"ras"|"82"`.
  Легаси `1cras.toml`/`~/.config/1cras/` читаются (фолбэк после переименования).
- Сниффер-петля для новых захватов: `cmd/mmmspy`, логи в `research/`.

## Правила

- Git: коммиты на английском и подписанные (SSH); публикация/пуш — только по
  явной команде владельца.
- **Серверы, которыми не владеешь, — только чтение и только готовым
  проверенным кодом** (Poll, списки, ctl). Экспериментальные рукопожатия,
  подмены версий и новые реплеи против чужого ragent могут уронить службу
  (проверено на печальном опыте) — не делать.
- **Реверс-эксперименты — только против собственных стендов** (docker,
  VM): новый код сначала проверяется на своих серверах.
- **Terminate/kill сеансов — только по явной команде владельца** (кого и когда).
- Перед правками общих файлов (main.go, app.go, adapter.go, ctl.go)
  перечитай текущее состояние с диска — бывает параллельная работа.

### Сборка — в контейнере (воркфлоу автора)

Автор собирает и тестирует только в контейнере — хостовой go-тулчейн на
машине автора не используется (кеши в докер-томах, хост не пачкаем).
CI на GitHub использует обычный setup-go — там это нормально.

Сборка/тесты/вет — через контейнер:

```
docker run --rm -v "$PWD":/src -w /src \
  -v lazy1c-gomod:/go/pkg/mod \
  -v lazy1c-gocache:/root/.cache/go-build \
  golang:1.27-alpine go test ./...
```

То же обёрнуто в `make test` / `make build` / `make vet` (Makefile). Артефакты
и временные файлы — только внутри папки проекта; после работы — убрать за собой.

## Особенности кода

- Кириллица: выравнивание только по рунам (pad/truncPad), не по байтам.
- Тесты против живых серверов — за env-флагами (RA82TEST=yes, RA82KILL=yes).
- Время 1С: 100-мкс тики с 0001-01-01, НЕ через time.Duration (переполнение).
