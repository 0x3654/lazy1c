# MMC-протокол ragent 1С:Предприятие 8.2 — находки реверса

Единственный способ программного администрирования кластера 8.2 —
недокументированный протокол MMC-консоли (ragent, порт 1540). RAS в 8.2 нет.
Этот документ — всё, что выяснено при реверсе (сентябрь 2026, платформа
8.2.19.130; стенды: своя Parallels VM и рабочий прод-стенд).

## Проволочный формат

- ragent сам здоровается при connect: константные 5 байт `53 F5 C6 1A 7B`.
  Это же — маркер авто-детекта 8.2 (RAS 8.3+ молчит до negotiate).
- Каждый кадр завершается трейлером `66 53 B2 A6`.
- Первое сообщение соединения — крипто-конверт: `[uint16 LE длина заголовка]
  [BOM + "n",\r\n{#base64:<материал>},\r\n{#base64:AQAB}]` (AQAB = RSA e
  65537) + интро в 1С-текстовом формате `{0,<uuid>,<seq>,4,...}`.
  Реплей конверта принимается ragent начисто; свой крипто-конверт пока
  не генерируем.
- Дальше — открытый текст (1С-текстовый формат, как .lst):
  `{<0=клиент|1=сервер>,<uuid контекста>,<seq>,<тип>,...}`.
- Аутентификация — **NTLM anonymous** в кортеже интро
  (`{"#",671507fd-...,{#base64 TlRMTVNT...}}`): type1 → challenge →
  type3. Доменный NTLM3 не нужен — анонимный проходит на обоих стендах.
- Версия платформы: ragent принял интро с `8.2.19.130` — несовместимую
  версию отверг бы («различаются версии»), поэтому принятая в рукопожатии
  версия = версия сервера. Извлекается из шаблона интро.

## Бинарные кадры данных

Запрос: `[41 95][16Б GUID-LE сессии соединения][8f][uint16 LE счётчик][тело]`.
Ответ: `[42 ...]`; асинхронные серверные пуши: `[43 ...]` — читать ответ
нужно как «первый кадр + дренаж накопившихся пушей», иначе рассинхрон.
Счётчик: старт значения не имеет (у MMC случайный), важна монотонность.
Keepalive MMC: `21 47 54 B3` каждые 5с; наш опрос сам является активностью.

### Словарь и наборы кадров

Тела кадров содержат **ссылки в потоковый словарь соединения**: одни и те
же кадры работают только на сервере, с которого сняты (VM-шаблоны не
работают на проде и наоборот), и только в исходном порядке следования.
Поэтому клиент несёт `frameSet` — упорядоченную цепочку, снятую с живой
MMC целиком (см. templates.go: `vmFrames`, `prodFrames`), и подбирает
набор автоперебором по «кто дал больше данных». Роли кадров: `clusters`,
`infobases` (второй 90Б-кадр!), `sessions`; остальные — служебные для
словаря. Полный список операций с новым сервером = новый захват через
mmmspy-петлю (cmd/mmmspy).

## Бинарная сериализация (эмпирически)

- `9a <len> <utf8>`, `97 <len> <utf16le>` — строки
- `91 <i64 LE>` — дата: **100-мкс тики с 0001-01-01** (не FILETIME!
  через time.Unix(secs−62135596800), Duration переполняется)
- `95 <16Б>` и `d5 <16Б>` — uuid: семья тегов `X5` (старшая тетрада —
  индекс словаря). Фильтр формы: версия 1–5, вариант 8-b, иначе это
  мусорные байты перед строкой (жадная семья съедала буквы: «азаркин»)
- `81/82/84/87/8b`, `a1/a2/a3` — флаги/концы; `9d <varint>` — ссылка на словарь

### Запись сеанса

```
[uuid-кандидаты перед базой: сеансовый + юзер, порядок НЕстабилен]
[9a база][91 t1][91 t2][9a хост][прил][пид][прил2][uuid×3][ru_RU×2][8.2.x][uuid][tz][хост][порт][ORGL8]
```

**Семантика uuid (главное для ID):**
- сеансовый uuid — уникален, наблюдается с тегом `d5`, стабилен на всё
  время жизни сеанса (проверено: ID совпадают между опросами 37/37);
- uuid пользователя — повторяется у всех сеансов одного юзера, тег `95`;
- порядок в записи пляшет от словарного сжатия → роли разрешаются
  пост-пасом `resolveSessionIDs`: частотность по всем записям + теги.

### Запись кластера

`[uuid-контекст][uuid-кластера] группой подряд, [имя?][хост][пид]`;
uuid кластера — последний в группе; имени может не быть — фолбэк на
host из адреса конфига. Числоподобные строки — пид rmngr, отбрасываются.

## Terminate (завершение сеанса)

Кадр (169Б) несёт **два слота жертвы**: `[107:123]` = uuid пользователя,
`[146:162]` = сеансовый uuid (оба из записи сеанса; GUID-LE).
Рецепт: Dial → FetchAll (построить словарь!) → TerminateWith. По мёртвой
жертве сервер молчит (только пуш) — не путать с отказом. Ответ `42` = принят.
Проверено живьём на прод-стенде.

## Скорость

Полный опрос (dial + рукопожатие + 13 кадров) ≈ 2.3–2.5с через VPN.
На персистентном соединении словарь уже построен → достаточно 2 кадров
(базы + сеансы) → **~230–300мс (10×)**; обрыв → авто re-dial (~2.4с).

Грабли (было в TUI, 2026-09): быстрый опрос приносит **настоящие uuid баз**
(`[9a имя]…[f5 uuid]`, FetchQuick их собирает), полный — только имена.
Если базы получают настоящий uuid, а сеансы — детерминированный
`NameUUID(имя)`, связка сеанс↔база рвётся со второго опроса: все сеансы
осиротели и падали в «без известной базы» в конец кластера. Обе стороны
должны резолвить uuid одинаково (`ibID`: настоящий → иначе NameUUID).

## Реверс 8.3-MMC: статус (16.09.2026)

Эксперимент с подменой версии в реплее (конверт + NTLM1 + NTLM3 — версия
сидит в КАЖДОМ кадре, формат {"S","8.2.19.130"}):
- с 8.2-версией сервер 8.3 отвечает «Различаются версии клиента и сервера
  (8.2.19.130 - 8.3.27.2130), клиентское приложение: Консоль кластера» —
  реплей распознаётся как консоль, каркас общий;
- с версией сервера ошибка исчезает, конверт/NTLM1 принимаются, но после
  NTLM3 сервер молча закрывает соединение — на чужом дев-стенде ragent
  упал (1540 refused, кластер на 1541 жив). **Вывод: NTLM3-реплей
  8.2 с чужой версией укладывает ragent 8.3 — против живых серверов не
  повторять, сначала эталонный захват настоящей консолью 8.3** (mmmspy).
Тот стенд реально был 8.3.27.2130 (внутренняя документация устарела).

## Наблюдение: ragent 8.3 на :1540 (15.09.2026)

На рабочих серверах без службы RAS (:1545 закрыт), но ragent 8.3/8.5 слушает :1540.
Проба нашим MMC-клиентом 8.2: приветствие совпадает (auto-детект считает его
8.2), на auth-кадр сервер отвечает ошибкой «Различаются версии клиента и
сервера» (uuid-ответ есть, текст ошибки внутри). RAS-протокол (negotiate/
connect) на :1540 не отвечает (таймаут). Вывод: на :1540 у 8.3 — родственная
MMC-линия с другой версией протокола в кадрах; потенциальный третий движок
(«83-MMC») для кластеров без RAS-службы. Захваты для реверса — mmmspy против
кластера 8.3 (нужна MMC-оснастка 8.3 или rac-трафик RAS:1545 для сравнения).

## Чего пока нет

Полные карточки баз (СУБД/РЗ/блокировки), соединения, блокировки, рабочие
процессы — нужны дополнительные захваты MMC (петля srv82 → cmd/mmmspy,
лог → templates.go). Собственный крипто-конверт вместо реплея.
